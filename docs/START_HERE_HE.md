# FoodLogger - מתחילים כאן

FoodLogger היא אפליקציה לזיהוי מזון מתמונות באמצעות Python ו־TensorFlow,
לחישוב ערכים תזונתיים לפי משקל המנה ולניהול יומן ארוחות אישי באמצעות חשבון משתמש.

## מה כלול

- ממשק באנגלית, מותאם לטלפון, לצילום ולהעלאת תמונות.
- הרשמה, התחברות ויומן נפרד לכל חשבון. קוד שחזור מוצג פעם אחת בעת ההרשמה.
- צילום ברקוד של מוצר או הזנת הספרות, חיפוש ב־Open Food Facts ואישור הערכים.
- הזנה ידנית של תווית תזונה, כולל סוכרים, סיבים ומלח, וכמויות בגרמים או במ״ל.
- זיהוי אמיתי באמצעות MobileNetV2 מאומן מראש, עם הצעות ואפשרות לתיקון ידני.
- קטלוג של 27 מזונות, מהם 23 ממופים למודל ברירת המחדל.
- חישוב קלוריות, חלבון, פחמימות ושומן לפי מספר הגרמים שהזנת.
- יומן ארוחות שנשמר ב־SQLite, מעבר בין תאריכים, מחיקה וייצוא CSV.
- API מתועד, בדיקות אוטומטיות ותהליך אימון ופיין־טיונינג למודל משלך.

## הרצה ב־Mac או Linux

יש להתקין Python 3.11 או 3.12. פתח Terminal בתוך תיקיית הפרויקט:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e ".[ml,dev]"
foodlogger download-model
foodlogger
```

פתח בדפדפן: [http://127.0.0.1:8000](http://127.0.0.1:8000).
כדי לעצור, לחץ Ctrl+C בחלון ה־Terminal.
בהרצות הבאות מספיק להפעיל את הסביבה עם `source .venv/bin/activate` ואז `foodlogger`.

ב־Windows משתמשים ב־`python` ובפקודת הפעלה `.venv\Scripts\Activate.ps1` ב־PowerShell.
TensorFlow 2.20 מתאים ל־Mac עם Apple Silicon. ל־Intel Mac אפשר להשתמש ב־Docker,
או להריץ רק את היומן עם `python -m pip install -e ".[dev]"` ללא זיהוי תמונה.

ההתקנה הראשונה כוללת ספריות למידת מכונה ולכן עשויה להימשך מספר דקות.
הורדת משקלי המודל דורשת אינטרנט; לאחר מכן התמונות מעובדות על המחשב שמריץ את
האפליקציה, ולא נשלחות לשירות זיהוי חיצוני. אין צורך במפתח API או בכרטיס מסך.

## שימוש באפליקציה

1. צור חשבון ושמור את קוד השחזור. ללא הקוד לא ניתן לאפס סיסמה שנשכחה.
2. העלה תמונה ברורה של מזון יחיד, למשל בננה או פיצה.
3. בדוק את הזיהוי. אם הוא שגוי או אינו בטוח, בחר את המזון מהרשימה.
4. הזן את המשקל בגרמים ובחר ארוחה.
5. הוסף ליומן ועיין בסיכום התזונתי היומי.
6. עבור בין תאריכים לצפייה בארוחות קודמות, ומחק או ייצא ארוחות לפי הצורך.

תיעוד ה־API זמין בכתובת [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs).

אין דרך להסיק משקל מדויק מתמונה רגילה. ערכי התזונה המצורפים הם אומדנים
בלבד, ואינם מאגר תזונתי מאומת. המודל המוכן מזהה קטגוריות ImageNet מוגבלות;
הוא לא מאומן במיוחד על כל המנות האפשריות ולא מפרק צלחת למרכיבים.

## אימון מודל מותאם אישית

הוראות להכנת מערך תמונות, אימון, פיין־טיונינג והפעלת מודל מותאם אישית נמצאות
ב־[README](../README.md). המודל המצורף כברירת מחדל מאומן על ImageNet;
תוצאות אימון על מערך נתונים משלך נרשמות בקובץ `metrics.json`.

## איפה הנתונים והקוד

היומן נשמר בקובץ `runtime/journal.sqlite3` בתוך תיקיית ההרצה. שמור אותו אם תרצה
להעביר את היומן. התמונות שהעלית אינן נשמרות. הקוד נמצא ב־`src/foodlogger`,
והבדיקות ב־`tests`. הרץ `pytest` מתוך הסביבה הווירטואלית לבדיקת הפרויקט.

הסביבה הווירטואלית, מסד הנתונים, מערכי התמונות ומשקלי המודלים מוחרגים
מניהול הגרסאות באמצעות `.gitignore`.

## מוצרים וברקודים

בלשונית Barcode אפשר לצלם את הברקוד, להעלות תמונה שלו או להקליד את הספרות.
האתר מציג את הערכים הזמינים ב־Open Food Facts. יש לבדוק את התווית ואת הכמות
שאכלת לפני השמירה. ערך שלא נמצא נשאר ריק; קלוריות ושלושת אבות המזון נדרשים
לשמירה. אם המוצר לא נמצא, אפשר למלא את התווית ידנית. במוצר נוזלי בחר במ״ל
רק כאשר הערכים שעל התווית נתונים ל־100 מ״ל.

הברקוד נשלח למאגר המוצרים; תמונות וסיסמאות לא נשלחות אליו. האתר מעבד תמונות
בזיכרון השרת ואינו שומר אותן. פרטי הארוחות נשמרים בחשבון המשתמש על השרת.

## פריסה ציבורית ב־Render

קובץ `render.yaml` מגדיר שרת Python עם TensorFlow ודיסק קבוע עבור מסד הנתונים.
התצורה דורשת משאבים בתשלום; יש לבדוק את המחיר העדכני ב־Render לפני יצירתם.
הוראות הפריסה, האחסון והגיבוי נמצאות ב־[תיעוד הפריסה](DEPLOYMENT.md).
התצורה במאגר אינה מעידה כשלעצמה שהאתר כבר פורסם.
