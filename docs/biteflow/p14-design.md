# P14 local measurement preparation

The user explicitly approved local P14 only after verification of `6c1825e`, with every gate/rollback caveat retained, AI mocked and no production changes or invented post-release metrics. This approval permits preparation despite the unmet release-entry gate; it does not constitute a release or approve telemetry collection. Full P14 remains BLOCKED.

The approved roadmap P14-A/B and implementation-plan sections6/10 require real usage/reliability dashboards, explicit samples/windows, minimized data and an evidence-backed backlog. Existing P13 contains synthetic timings, an unactivated monitoring proposal and release thresholds, but no approved release, observed aggregate dataset, telemetry collector or dashboard. Existing AI accounting and personal journal trends are not population adoption/retention metrics and must not be repurposed as such.

Implement an offline Python aggregate validator/analyzer and a local report command, following existing `scripts/` and deterministic-domain patterns. No app/API/DB/native integration, collector, remote destination, scheduler, live AI, additional dependency or migration. The alternative of enabling collection is outside approval; documentation alone would leave arithmetic/input/error paths untested. This offline boundary makes useful progress without changing existing user flows.

Inputs contain only a fixed catalogue of aggregate numerators/denominators, counts, histogram buckets or USD totals, one explicit UTC window and release/source digests. Reject unknown fields/metrics, duplicate JSON keys, invalid numbers, malformed windows and excessive input sizes. No raw events, user/account/device IDs, text, images, audio or free-form feedback. Shape validation is not proof of anonymization: policy, consent, cohort size, retention and human review remain gates.

Evidence kinds are `none`, `synthetic`, `unverified_observation`. None means all metrics absent; synthetic always remains visibly synthetic; supplied observations are declarations, never automatically verified production evidence. Missing/partial/no-sample data remains null with reasons, never invented zero. Rates expose exact counts; repeat/query timing reports histogram quantile upper bounds rather than pretending exact percentiles. Logged days use eligible complete user-weeks with a seven-day maximum. Cost is an explicitly supplied decimal USD total, never inferred from quota or attempts.

The default report has no observations. A separate explicitly synthetic fixture validates calculations. Standalone JSON/HTML and a deterministic evidence-gap backlog show the window, coverage, sample counts, evidence kind, input hash and blocked phase status. They use no scripts, remote fonts, trackers or network calls. Invalid inputs fail without echoing their contents or overwriting prior output. The command writes a new report directory only. A human-facing measurement protocol records metric definitions, observation boundaries, proposed threshold comparisons and evidence/feedback backlog; absent post-release evidence prevents conclusions about adoption, retention, accuracy or improvement.

P14 acceptance remains blocked until an approved release actually occurs and minimized, reviewed observations support dashboards and a product-owner-approved backlog. P13 thresholds remain proposals, not auto-enforced release authorization. All prior gates and compatible P13 rollback source floor `4d97784` remain. Removing only this additive offline tooling reverts P14 preparation without reverting P13 cleanup/security.
