# P11 — local Android Health Connect design

Approved scope: roadmap P11-A/B/C and F17 only, user-approved local carry-forward of every P10/inherited gate. Base `579a006f5e947a651283e32659684c8b0cf6f3f8`. No P12, live AI, production, signing portal/store changes, push, merge or deployment.

## Capability/toolchain review before implementation

Expo 57.0.27 / RN 0.86.3. Default Java lookup fails, but Android Studio bundles JDK 21.0.10. Android SDK contains platforms 36/36.1, build-tools 35/36/36.1/37, NDK 27.1.12297006, platform-tools/emulator and an Android 37 ARM64 system image. Per-command JAVA_HOME/ANDROID_HOME can use these without changing system settings. Initial offline Gradle build reaches dependency resolution, then fails on uncached existing dependencies. Online dependency resolution/build is being measured. Device runtime acceptance is not inferred from installed tools. Existing generated Release configuration uses a debug key; a release-variant build is not a store-signed release.

Official SDK choice: stable `androidx.health.connect:connect-client:1.1.0`, not an alpha. Add Android support to the existing tracked Expo local module with the official scaffolder. No hand edits to generated android/ios directories. Feature flags default off. Health Connect availability distinguishes unavailable, install/update required and available. Permission state is queried each operation. Read WeightRecord/StepsRecord only; write NutritionRecord/HydrationRecord only; no background/history permission. Required provider query, rationale activity and Android 14 permission-usage alias are generated by config plugin. Privacy text must have operational/store review before live release.

## Reuse and interfaces

- Reuse P10 owner scope, sample ID, revision/tombstone and snapshot contracts. A NutritionRecord represents one existing nutrient sample (other fields remain null), avoiding combined-record revision ambiguity; HydrationRecord represents manual water. Namespaced clientRecordId + clientRecordVersion provide upsert semantics. Delete only exact owned clientRecordIds. Native revision checkpoints protect stale tombstone replay.
- Point measurements are represented by a minimal 1 ms interval required by Health Connect interval records; start is the original instant, zone offset derives from its original canonical timezone. This is an adapter interval, not a claimed measured eating duration.
- Keep iOS adapter and old API routes compatible. Introduce platform selection plus optional incremental import methods on shared HealthPort. Separate Android owner storage key and default-off server/client flag; existing iOS key remains unchanged.
- Pull weight and steps separately with bounded pages. Capture each change token before initial 30-day snapshot; persist snapshot pagination and change-token state only after backend acknowledgement. Persist pending page before upload; retry stable records/tombstones after lost acknowledgements. Permissions are checked again before upload. Deselecting a kind drops its pending transfer but does not advance its cursor. No nutrition read or import loop.
- Expired changes tokens restart a bounded 30-day read/deduplication and keep a visible recovery warning: missing historical deletions cannot be inferred from absence. No blanket complete-history claim. Missing/denied data never means zero or deletion.
- New `health_connect_imports` owner-private table retains source ID, latest source modification time, source offsets, canonical display timezone, payload, tracking ID and deletion tombstone. Apple receipts are untouched. Upserts use latest modification time, reject equal-time conflicting payloads, preserve user deletion, and update only matched Health Connect weight rows. Deletions target only those imported rows, never food/manual/Apple rows. Unknown deletions leave a tombstone to reject stale replay.
- Health Connect supplies offsets, not IANA timezone names. Preserve source offsets separately. Choose the device IANA timezone explicitly as the journal display timezone at first import, retain it on replays/updates, and retain original instants. UI discloses this choice; never label the journal timezone as a measured original timezone.
- EN/HE settings expose install/manage permissions, selected data, denied/revoked status, retry, disconnect, incomplete-history warning and source attribution. The permission activity temporarily backgrounds Android; distinguish an active permission request from ordinary backgrounding so it can complete without restarting unauthorized sync. Account/logout generation guards always apply.

## Verification / gates

TDD: provider receipt ordering/isolation/timestamps/deletion; fake native permission/record policy; queue page/ack failure, token expiry, deselection, partial grant and account switch; config generation and EN/HE UI. Run all backend/mobile/browser/PG checks, lint/typecheck, packaging/exports, native Android Debug/Release and native unit tests. Native tests use fake clients/synthetic records, never a person's Health data. Emulator capability evidence is optional early evidence; physical-device E2E-16/19/20 and production signing remain mandatory/open. Independent review, one author fix pass, actual counts and complete inherited gates at checkpoint.

Rollback: disable Android sync flags, pause/disconnect clients, preserve shared export mappings and new import receipts/tombstones and compatible pending queues. Retain table/read/delete grants for privacy erasure; revoke writes rather than drop schema. Never erase external records or reset clientRecordId/version while native records exist. Preserve all previous label-draft/measurement/notification/Health rollback caveats.
