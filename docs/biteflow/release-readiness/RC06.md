## Implemented requirements and existing behavior retained

### RC06-A: exact macro threshold

`mobile/src/domain/goals.ts` now compares scaled integer fractions directly. It does not convert to floating point before evaluating the strict `>10%` warning and does not modify saved kcal. Python's existing Decimal calculation was already correct and was left unchanged.

The16 shared, hand-calculated cases in `mobile/src/test-fixtures/goal-warning-cases.json` run through both the TypeScript domain and Python API: exact, just-under and just-over ±10% at integer and decimal targets; null kcal/protein/carbs/fat. Specifically,200kcal with20g protein/17g carbs/8g fat gives220 and no warning;20.00001 warns,19.99999 does not. Decimal200.1/220.11 exposed the old floating-point bug. API tests assert saved values are unchanged.

### RC06-B: language, foreground refresh and widget warnings

- `ServingSelector.tsx` translates app-owned serving units and source-confidence explanations in English/Hebrew. Source measure labels remain explicit verbatim quotes; original portion units and provenance remain intact. Unknown confidence is presented as unknown, not verified.
- `FoodRestrictions.tsx` refreshes when the focused app returns from background/inactive, rejects older responses and defers reads during an active write. Dirty preferences and ingredient reviews survive refresh. If server preference/source/review versions change, saving is blocked until the person explicitly discards edits and loads latest. Failed refresh does not erase the visible data. No new API or blind overwrite was added.

No lint exclusion or suppression was introduced.

The existing widget config plugin now retains the `iw` resource alias alongside `b+he`, without adding duplicate app language choices. A plugin regression and actual Debug/Release APK resource checks cover this. The transient `values-b+he` attempt was rejected because lint still warned; final source uses canonical `values-iw`.
