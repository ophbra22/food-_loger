Scope: local unsigned iOS simulator builds and Android local debug-signed builds only; no device/store/signing approval is implied. Source baseline e7f7c9d, branch codex/biteflow-rc00-05. Final command matrix and hashes will be linked from the wave checkpoint.

## Fix and evidence

Reproduced clean iOS Release failure (exit65): ExpoModulesJSI prebuilt Swift interface used a different compiler and could not resolve `__ObjC::expo`. Set `ios.usePrecompiledModules:false` in `mobile/app.config.ts`, a supported SDK57 option. No generated native source was edited. Clean separate derived-data builds now pass with Xcode27.1/Swift6.4: enabled Release409.73s and Debug430.35s, including the widget extension and native modules.

Sources read: [Expo SDK57](https://docs.expo.dev/versions/v57.0.0/), [SDK57 build properties](https://docs.expo.dev/versions/v57.0.0/sdk/build-properties/). Support for source mode is documented; success on the installed toolchain is established by local build logs, not inferred from documentation.

Clean Android enabled Debug/Release succeeded; 22 JVM cases (12 Health,10 widget) passed. Swift policy/file executables passed29 checks (13 widget,3 file/capability,13 Health). These exercise policies, not actual HealthKit/Health Connect/WidgetKit execution on a device. Java is available; the historical missing-JDK issue is not reopened.

Disabled-mode native builds and final artifact checks are in progress at this draft checkpoint. Full Android lint remains RC02, separate from successful compilation. Native dependency/build warnings remain visible. Hosted CI, a second clean host, signed device binaries and release provisioning are unverified.
