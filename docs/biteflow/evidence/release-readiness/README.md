# Local RC00–RC05 evidence

Final implementation: `5455c494067ea8474affb6375b3a40ff84c1ff02`. [Checkpoint](../../release-readiness/checkpoint-RC00-05.md), [every recorded command](../../release-readiness/verification-results.md), [retained gates](../../release-readiness/gate-register.md).

- RC00 contains initial environment and baseline results. RC01–05 include targeted RED/GREEN, failed diagnostic and final runs. `final/` holds combined suites, package/cleanup/source checks and the independent-review transcription/ledger.
- JSON command records contain exact argv, working directory, exit and executor duration. Final records additionally contain UTC start, source SHA, dirty reporting paths and public flags. Older records are intermediate wave evidence; an exact source SHA/date absent from the original record must not be invented retrospectively.
- Large raw output is losslessly gzip-compressed. `archive-manifest.json` records raw bytes/hash and stored hash; small tail files are convenience views. Failed commands remain failed, including expected TDD RED runs. The checkpoint selects final acceptance evidence; exit0 alone is not release acceptance.
- Binary APKs, simulator app directories, Docker export and Python wheel/sdist remain in the owned `runtime/rc00-05-20261018/` directory, with hashes in manifests. No private database or temporary DB credential file is archived. The historical P13 recovery APK is retained separately and is not a current operational downgrade candidate.
- Native modes are the five local capability flags: Health, Health Connect, widgets, voice, reminders. Cleared exports and regenerated native projects are checked against actual compiled permission/metadata values. Account-export disabling is a distinct rollback flag tested in RC05; physical validation of a compatible export-disabled candidate remains RC19. All API origins used for builds point to loopback. Builds did not run speech/Health/AI operations.
- iOS Debug/Release builds sharing a Pods directory must run sequentially because Hermes setup replaces shared binaries. Separate derived-data directories are still used. Android builds use the recorded JDK/SDK and6GiB/max2workers; regenerate first, then build, instead of mixing parallel clean/build tasks.
- The archived helpers are reproducibility copies, not application code. To rerun them in an authorized local test checkout, copy them into its fresh owned `runtime/rc00-05-20261018/` directory (their relative root calculation expects that location), use matching installed tools and inspect command records first. `postgres.py start` creates only an owned disposable loopback database and writes a private local credential file; `stop` validates ownership and removes that container/volume/file. Never supply a production or staging DSN. Package checks require new output directories and never accept old report output.
- Advisory registry/SDK/package downloads occurred. Secret scanning used `--no-verify`; provider/account credentials and real AI were not invoked. Real-model tests were deliberately not enabled. Image inspection/import smoke used read-only/network-disabled containers; the shipping image's69 package files match final source. Full image and native lint gates remain open despite local test success.

Public toolchain/package metadata is included. Bounded secret scanning excludes binary blobs and does not prove absence of all credentials or perform rotation. The Python image's resolved dependency versions differ from the shared local test environment; inventories preserve this gap rather than treating one environment as the other.
